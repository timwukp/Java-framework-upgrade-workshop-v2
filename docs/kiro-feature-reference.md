# Kiro feature reference for this workshop

Every Kiro feature used in the modules, with the official documentation page. Facts were checked
against kiro.dev on 2026-10-09 (Kiro IDE 1.x, CLI V3). If the product has moved on, the linked docs
are authoritative.

## Features used

| Feature | What to know for this workshop | Docs |
|---|---|---|
| Workflows / built-in agents | The "Let's build" screen offers **Spec, Quick Spec, Bug Fix, Plan**. Skipping it gives the **Default** agent. Switch agents mid-session with the agent selector. In the IDE you pick these from the UI; `/spec` and `/plan` are CLI commands. | [Chat](https://kiro.dev/docs/ide/chat/), [Slash commands](https://kiro.dev/docs/ide/chat/slash-commands/) |
| Plan | Read-only planning. Nothing is saved under `.kiro/specs/`. | [Plan](https://kiro.dev/docs/specs/plan/) |
| Specs | Feature specs (Requirements-First or Design-First) produce `requirements.md`, `design.md` and `tasks.md` under `.kiro/specs/<name>/`. Requirements use EARS ("WHEN … THE SYSTEM SHALL …"). **Run all Tasks** runs incomplete required tasks in dependency waves; tasks within a wave run concurrently. **Sync Files** updates tasks after requirements change. | [Specs](https://kiro.dev/docs/specs/) |
| Bugfix specs | `bugfix.md` captures current vs expected behavior and regression guards ("SHALL CONTINUE TO"). | [Bugfix specs](https://kiro.dev/docs/specs/bugfix-specs/) |
| Quick Spec | Generates requirements, design and tasks in one pass, without approval gates. Fits a change whose scope is already defined (in Modules 3 and 4, a whole stage that the playbook describes); you review the files before any task runs. For high-stakes work the docs recommend a Feature spec with review gates. | [Quick Spec](https://kiro.dev/docs/specs/quick-spec/) |
| Autopilot / Supervised | Autopilot (the default) applies changes and offers Revert. Supervised pauses after edits for per-hunk Accept / Reject. The setting is `kiroAgent.agentAutonomy`. The workshop recommends **Supervised**. | [Autopilot](https://kiro.dev/docs/ide/chat/autopilot/) |
| Context providers | `#codebase`, `#file`, `#folder`, `#git diff`, `#terminal`, `#problems`, `#url`, `#code`, `#repository`, `#current`, `#steering`, `#docs`, `#spec`, `#mcp` | [Chat](https://kiro.dev/docs/ide/chat/) |
| Code into chat | Select code and press **Cmd+L** (macOS) / **Ctrl+L** to add it to the current chat. **Cmd/Ctrl+Shift+L** starts a new session with it. Inline chat was retired in IDE 1.0. | [What's new in 1.0](https://kiro.dev/docs/ide/whats-new-v1/) |
| Checkpoints | A checkpoint is created per prompt. Restore rolls back files and context; Revert undoes the last turn. **Manual edits, shell commands (Maven, OpenRewrite) and MCP changes are not captured**, so commit with git before each agent run. | [Checkpoints](https://kiro.dev/docs/checkpoints/) |
| Workspace trust | An untrusted workspace does not load the repo's steering, custom agents, MCP config, skills or workflows, and prompts for every shell command. | [Permissions](https://kiro.dev/docs/permissions/) |
| Permissions | Rules live in `~/.kiro/settings/permissions.yaml` (user) or a per-workspace file under `~/.kiro/workspace-roots/`, so they can't be shipped in a repository. Prompts always offer Allow and Deny; **Always allow** / **Always deny** appear only when Kiro can verify a working saved rule. Without rules: workspace reads, read-only git and system-info commands (`pwd`, `whoami`, `uname`) run silently; everything else prompts. | [Permissions](https://kiro.dev/docs/permissions/) |
| Steering | `.kiro/steering/*.md` with front matter `inclusion: always` (default), `fileMatch` + `fileMatchPattern`, `manual` (reference as `#name` or `/name`), or `auto` (+ `name`, `description`). File references: `#[[file:path]]`. **Generate Steering Docs** creates `product.md`, `tech.md` and `structure.md`. `AGENTS.md` is always included. | [Steering](https://kiro.dev/docs/steering/) |
| Hooks | Files are `.kiro/hooks/*.json` with `"version": "v1"`.<br>Triggers: `SessionStart`, `Stop`, `UserPromptSubmit`, `PreTaskExec`, `PostTaskExec`, `PreToolUse`, `PostToolUse`, `PostFileCreate`, `PostFileSave`, `PostFileDelete`.<br>A `command` action receives JSON on stdin, uses no credits, and passes **stderr** to the agent on failure. An `agent` action injects a prompt.<br>Use `exit 2` to block `PreToolUse`, `UserPromptSubmit` and `PreTaskExec`.<br>File hooks fire only on agent edits. Default timeout is 60 s.<br>The shipped `verify-after-spec-task` runs one `mvn -B clean verify` per spec task: on success the agent gets the `Tests run` line and `BUILD SUCCESS`, on failure the last 80 lines on stderr. It still passes when fewer tests run, so read the count. That command output was verified as a plain shell command on Linux in the 2026-10-10 dry run; how Kiro passes it to the agent was not. | [Hooks](https://kiro.dev/docs/hooks/), [Hooks in 1.0](https://kiro.dev/docs/ide/whats-new-v1/hooks/) |
| Custom agents | `.kiro/agents/<name>.md`: front matter is the config, the body is the system prompt. `tools` uses tags (`read`, `write`, `shell`, `web`, `subagent`); `permissions.rules` sets per-agent rules. By default a custom agent inherits the default resources (steering, skills, `AGENTS.md`) unless `chat.disableInheritingDefaultResources` is set; `resources` (`file://…`, `skill://…`) adds more. The steering and skills pages say custom agents don't load them otherwise, so list them in `resources` explicitly: it works either way. The workshop's `migration-reviewer` has no `write` tool and is instructed not to modify files; it can still run shell commands, so check `git status` after a review. | [Custom agents](https://kiro.dev/docs/custom-agents/), [Creating agents](https://kiro.dev/docs/custom-agents/creating/) |
| Sub-agents | Delegate to another agent ("Use the migration-reviewer agent to …"). Sub-agents run in parallel, each with its own context, in the same working tree: only one of them should run Maven. | [Sub-agents](https://kiro.dev/docs/custom-agents/subagents/) |
| Skills | `.kiro/skills/<name>/SKILL.md` with `name` (equal to the folder name) and `description`. Kiro activates a skill when a request matches its description, or when you type `/<name>`. | [Skills](https://kiro.dev/docs/skills/) |
| Powers | Agent Plugins format: `plugin.json` plus optional `skills/` and `mcp.json`. Keywords in `plugin.json` activate the power. To install: Powers panel → **Add Custom Power** → *Import power from a folder* or *Import power from GitHub* → **Install**. The registry is at [kiro.dev/powers](https://kiro.dev/powers/). | [Create a power](https://kiro.dev/docs/powers/create/), [Install](https://kiro.dev/docs/powers/installation/) |
| MCP | `.kiro/settings/mcp.json` (workspace) and `~/.kiro/settings/mcp.json` (user) are merged; the workspace wins. | [MCP configuration](https://kiro.dev/docs/mcp/configuration/) |
| Kiroignore | gitignore syntax; works in the IDE and CLI V3, not on Web. In the IDE, add `.kiroignore` to `kiroAgent.agentIgnoreFiles`. | [Kiroignore](https://kiro.dev/docs/kiroignore/) |
| Java support | JDK 17+ recommended (Amazon Corretto), Maven/Gradle, Open VSX *Extension Pack for Java* and *Spring Boot Extension Pack*. | [Java guide](https://kiro.dev/docs/guides/languages-and-frameworks/java-guide/) |
| Kiro CLI | `kiro-cli`; headless `kiro-cli chat --no-interactive` with `KIRO_API_KEY` (API keys require a paid plan). | [Headless mode](https://kiro.dev/docs/cli/headless/) |
| Kiro Web | Connects GitHub or GitLab, works in a cloud sandbox, and opens a pull request. Autonomous mode is opt-in. | [Kiro Web](https://kiro.dev/docs/web/) |
| Workflows (multi-agent) | Background multi-step runs. Off by default: turn them on in Workspace Configuration → Workflows (Agent Focus) or set `kiroAgent.workflows.enabled`, then start a new chat session. | [Workflows](https://kiro.dev/docs/workflows/) |
| Plans and credits | Free: 50 credits/month. Paid tiers: Pro, Pro+, Pro Max, Power. Models have credit multipliers (Auto = 1.0x). | [Pricing](https://kiro.dev/pricing/), [Models](https://kiro.dev/docs/models/available-models/) |
| Data protection | Enterprise content is not used for service improvement. Free and individual-tier content may be used unless you opt out. | [Data protection](https://kiro.dev/docs/privacy-and-security/data-protection/) |

## What older material often gets wrong

| Claim seen in older guides | Current reality | Docs |
|---|---|---|
| "Run the Kiro *Upgrade Java version* transformation from the Command Palette" | Kiro has no built-in Java upgrade / code transformation. That was an Amazon Q Developer feature (`/transform`). Use a spec plus the agent, optionally with OpenRewrite or the AWS Transform power. | [Migrating from Q Developer](https://kiro.dev/docs/upgrade-guides/migrating-from-q-developer/) |
| Hooks are `.kiro/hooks/*.kiro.hook` files with `when` / `then` | Since IDE 1.0, hooks are `.kiro/hooks/*.json` (`version`, `trigger`, `matcher`, `action`). Legacy hooks don't run until migrated. | [Hooks in 1.0](https://kiro.dev/docs/ide/whats-new-v1/hooks/) |
| "Create a manual (user-triggered) hook" | New Manual hooks can't be created. Use a `manual` steering file and run it as `/<name>`. | [Hooks in 1.0](https://kiro.dev/docs/ide/whats-new-v1/hooks/) |
| "Add trusted commands" | Replaced by `permissions.yaml` rules and Always allow. | [What's new in 1.0](https://kiro.dev/docs/ide/whats-new-v1/) |
| "Press Alt+C for inline suggestions" / "open the Code Issues panel" | Not part of Kiro IDE 1.x. | [Keyboard shortcuts](https://kiro.dev/docs/ide/editor/keyboard-shortcuts/) |
| "Use inline chat in the editor" | Retired in IDE 1.0. Use Cmd/Ctrl+L. | [What's new in 1.0](https://kiro.dev/docs/ide/whats-new-v1/) |
| "Powers panel → Build a Power → Export / Import" | Powers use the Agent Plugins format. Install with Add Custom Power → Import from folder / GitHub; share through a public GitHub repo. *Build a Power* is a power in the registry, not a panel button. There is no Export. | [Create a power](https://kiro.dev/docs/powers/create/) |
| A power contains `POWER.md` + `steering/` | `POWER.md` is the legacy format (still works). New powers use `plugin.json` + `skills/` + `mcp.json`. | [Create a power](https://kiro.dev/docs/powers/create/) |
| "Vibe vs Spec sessions" | Sessions start from the workflow picker (Spec, Quick Spec, Bug Fix, Plan) or the Default agent. | [Chat](https://kiro.dev/docs/ide/chat/) |
